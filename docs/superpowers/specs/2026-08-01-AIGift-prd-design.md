## 1. 概述

### 1.1 产品定位
基于 AI 的微信小程序礼物推荐助手。用户描述送礼对象画像与送礼场景，AI 生成可执行的礼物建议清单；用户填写的信息越完整，推荐越准确。系统记录用户反馈（采纳/不采纳）并用于优化后续推荐。

**一句话价值主张**：解决"不知道送什么"的决策难题，让每一次送礼都精准到位。

### 1.2 背景与问题
- **用户痛点**：送礼场景频繁（生日、节日、纪念日等），但选礼耗时、容易踩雷、预算难把控。
- **现有方案不足**：搜索引擎结果泛泛、电商推荐偏商业化、问朋友效率低。
- **机会**：大模型（如 DeepSeek）成本低、推理强，能基于多维画像生成个性化、可解释的建议。

### 1.3 商业模式
免费增值 + 广告变现（激励视频为主）。未来增加电商导购佣金作为第二收入。

### 1.4 业务目标与成功指标
| 维度 | 目标 | 关键指标（KPI） |
|---|---|---|
| 用户留存 | 培养送礼场景下的持续使用习惯 | 次日留存率、7 日留存率、30 日留存率、DAU、人均使用时长 |
| 广告收入 | 通过激励视频与展示广告实现变现 | 广告曝光量、激励视频完成率、eCPM、ARPU、人均视频次数 |
| 推荐质量 | 提供真正有用、可采纳的建议 | 采纳率、单次推荐平均采纳数、满意度评分、复用率 |
| 新增与转化 | 降低使用门槛、驱动裂变增长 | 注册转化率、推荐完成率、分享率、邀请转化率、K 因子 |

### 1.5 非目标（Out of Scope — MVP）
- 不做具体商品库与购买链接（V2 规划）
- 不做电商交易、支付、物流
- 不做社区/UGC 内容
- 不做深度机器学习推荐模型（MVP 采用轻量上下文方案）

## 2. 目标用户与场景

### 2.1 目标用户
**通用大众**——所有需要送礼的人。不限定年龄/性别/职业，覆盖中国互联网主流人群。

典型用户画像：
- 想给伴侣准备生日惊喜的年轻人
- 给父母/长辈挑选节日礼物的上班族
- 给领导/客户准备商务礼物的职场人
- 临时需要见面礼/回礼的人

### 2.2 核心使用场景
| 场景 | 频次 | 特征 |
|---|---|---|
| 生日送礼 | 高 | 时间明确，个性化要求高 |
| 节日送礼（春节/情人节/母亲节等） | 季节性高峰 | 流量爆发，预算跨度大 |
| 纪念日（恋爱/结婚） | 中 | 情感价值高，注重仪式感 |
| 感谢/道歉/探望 | 中低 | 场景驱动，临时性 |
| 商务送礼（领导/客户） | 中 | 预算较高，得体优先 |
| 乔迁/升职/毕业 | 低 | 里程碑事件 |

## 3. MVP 产品策略

采用**场景化运营型 MVP（方案 B）**：核心推荐闭环 + 场景化模板 + 节日提醒 + 分享裂变。每个功能精准对应一个核心指标：

| 功能 | 服务的指标 |
|---|---|
| 多维信息填写 + AI 推荐（核心闭环） | 推荐质量、留存 |
| 场景化模板（一键预填） | 新增与转化（降低门槛） |
| 节日/纪念日提醒 | 留存（召回） |
| 分享裂变（分享得次数） | 新增与转化（裂变） |
| 广告接入（Banner/插屏/激励视频） | 广告收入 |
| 额度系统（新人免费 + 视频 + 分享 + 每日登录） | 广告收入、留存 |

## 4. 核心用户流程

```
进入小程序
  → 微信授权登录（autoLogin）→ 发放新人免费额度（3 次）
  → [首页] 选择送礼对象（已有对象 / + 新建对象）
  → 填写/确认对象画像 + 推荐参数
       └ 可选：点击「场景模板」一键预填（生日/节日/纪念日/感谢/恋爱/商务…）
       └ 实时显示「推荐完整度 X%」与分档徽章
  → 点击「生成推荐」
       → 校验必填项（缺失则按钮置灰 + 提示）
       → 校验额度：
            ├ 有额度 → 直接调用 AI（扣 1 次）
            └ 无额度 → 引导「看激励视频 +3」或「分享好友 +2」或「每日登录 +1」
  → AI 返回建议清单（每条：名称 + 推荐理由 + 预估价格区间 + 购买渠道提示 + 匹配分）
       → 可能触发插屏广告（频控：首次推荐不插，每会话 ≤2 次）
  → [结果页] 用户对每条反馈：采纳 / 不采纳 / 收藏
       → 反馈写入历史，更新该对象的偏好上下文
  → 可选：「换一批再推荐」「分享卡片得次数」
  → [历史] 查看过往推荐，可「基于此再推荐」复用
  → [提醒] 为对象设置重要日期，到期收到订阅消息召回
```

## 5. 功能需求

> 标注：🟢 MVP 必做 ｜ 🔵 V2+ 未来

### 5.1 账号与登录 🟢
- **用户故事**：作为用户，我希望用微信一键登录，无需注册。
- **需求**：微信授权登录（`wx.login` + 云函数 `user/autoLogin`），以 `openid` 为唯一标识；首次登录发放新人免费额度。
- **验收标准**：用户进入即自动登录；额度正确发放并可在「我的」查看。

### 5.2 送礼对象管理 🟢
- **用户故事**：作为用户，我希望保存多个送礼对象，下次直接选用，避免重复填写。
- **需求**：对象的增删改查；支持多对象；推荐时可选择已有对象或新建。
- **验收标准**：可创建 ≥1 个对象；编辑后画像立即生效；删除后关联历史保留（按对象快照）。

### 5.3 推荐信息填写 🟢
- **用户故事**：作为用户，我希望通过表单+模板快速描述对象和场景，且被告知信息越全越准。
- **需求**：多维对象画像表单 + 推荐参数表单（详见第 7 章）；场景模板预设；完整度实时计算与提示。
- **验收标准**：必填项缺失时无法生成；完整度随填写实时更新；模板可一键预填。

### 5.4 AI 推荐 🟢
- **用户故事**：作为用户，我希望获得多条个性化、可解释、不踩雷的礼物建议。
- **需求**：多模型可切换（默认 DeepSeek）；输出结构化建议清单；规避禁忌；不重复历史（详见第 8 章）。
- **验收标准**：单次返回 N 条（默认 5）；每条含名称/理由/价格/渠道/匹配分；响应 P95 < 8s；失败有兜底。

### 5.5 反馈与历史 🟢
- **用户故事**：作为用户，我希望记录每次推荐与采纳情况，并能复用。
- **需求**：对每条建议标记采纳/不采纳/收藏；推荐记录按对象/时间分组；支持「基于此再推荐」。
- **验收标准**：反馈持久化；历史可按对象筛选；复用可带入上下文。

### 5.6 节日/纪念日提醒 🟢
- **用户故事**：作为用户，我希望在重要日期前收到提醒，不错过送礼时机。
- **需求**：为对象设置重要日期（生日/纪念日等，可设每年循环）；定时任务扫描并下发微信订阅消息。
- **验收标准**：到期当日（默认 9:00）收到提醒；支持每年循环；可在「我的」管理提醒列表。

### 5.7 广告接入 🟢
- **用户故事**：作为平台，我希望通过广告变现覆盖成本并盈利。
- **需求**：接入微信流量主 Banner、插屏、激励视频广告；频控策略保护体验（详见第 9 章）。
- **验收标准**：广告正常展示；激励视频完成后额度正确发放；插屏遵循频控。

### 5.8 额度系统 🟢
- **用户故事**：作为用户，我希望有免费额度，用完后能通过看视频/分享/登录补充。
- **需求**：额度查询/扣减/补充；激励视频回调校验；分享奖励；每日登录奖励（详见第 9 章）。
- **验收标准**：额度增减准确且有流水；不可超扣；跨会话一致。

### 5.9 分享裂变 🟢
- **用户故事**：作为用户，我希望分享给好友后获得奖励。
- **需求**：分享小程序卡片；被邀请者首次进入即记录邀请关系；邀请者获得额度奖励。
- **验收标准**：仅首次有效；奖励发放一次；K 因子可统计。

### 5.10 未来功能（V2+，PRD 标注但不实现）🔵
- **商品库 / 电商导购**：接入电商联盟（如淘宝客/京东联盟），推荐具体商品 + 购买链接，赚取佣金（第二收入）。
- **推荐质量分析后台**：采纳率/满意度看板，持续优化 prompt 与模型。
- **对象画像深度沉淀**：中度/深度学习，主动建模偏好。
- **多模型 A/B 对比与自动择优**。
- **送礼账本与历史分析**：年度送礼支出/对象分布。

## 7. 对象画像与推荐参数（核心数据输入）

|---|---|---|---|

| | 性别 | ✅ | 男/女/其他 |
| | 年龄段 | ✅ | 婴幼儿/儿童/少年/青年/中年/中老年/老年 |
| | 具体年龄 | 选填 | 数字（更精确） |
| | 生日 | 选填 | 日期（自动生成提醒） |
| | 星座 | 选填 | 由生日自动推算 |
| | MBTI | 选填 | 16 型 |
| 关系 | 关系类型 | ✅ | 恋人/配偶/父母/子女/兄弟姐妹/长辈/朋友/闺蜜/同学/同事/领导/客户/师生/其他 |
| | 亲密程度 | 选填 | 普通/熟悉/亲密/至亲 |
| 身份 | 职业/身份 | 选填 | 行业+职位（学生/上班族/自由职业/退休/医护/教师/程序员…） |
| | 人生阶段 | 选填 | 单身/恋爱中/已婚/有娃/备孕/空巢 |

### 7.2 推荐参数（描述"这次送礼"）
| 字段 | 必填 | 取值/说明 |
|---|---|---|
| 送礼场合 | ✅ | 生日/纪念日/节日(春节·情人节·母亲节·教师节·中秋·圣诞…)/感谢/道歉/探望/乔迁/升职/毕业/表白/见面礼/回礼/无特殊 |
| 预算区间 | ✅ | 0-50/50-100/100-300/300-500/500-1000/1000-3000/3000+ 元（或自由区间） |
| 送礼日期 | 选填 | 影响"是否来得及"（实物需物流 vs 虚拟即时） |
| 送达方式 | 选填 | 当面/快递/虚拟/不限 |
| 期望礼物类型 | 选填多选 | 实物/虚拟/体验(旅游·课程·服务)/DIY手工/红包礼金/不限 |
| 推荐条数 | 选填 | 默认 5 条，可选 3/5/8/10 |
| 个人想法/灵感 | 选填文本 | 用户已有初步想法，AI 据此优化 |
| 其他补充 | 选填文本 | 自由补充 |
| 历史参考 | 🔄系统自动 | 该对象过往推荐+采纳摘要（自动注入，用户无需填） |

### 7.3 完整度提示设计
- **进度可视化**：表单顶部 `推荐完整度 X%` + 进度条。
- **实时引导文案**：「再填写 2 项，推荐准确度将显著提升 ↑」。
- **分档徽章**：
  - 仅必填 → 「标准推荐」
  - 完整度 ≥ 60% → 「精准推荐」✨
  - 完整度 ≥ 85% → 「高精准推荐」🌟
- **必填兜底**：必填项缺失时「生成推荐」置灰 + 提示。
- **选填鼓励**：选填项旁标注「+精准度」。

## 8. AI 推荐设计

### 8.1 多模型抽象层（可切换，默认 DeepSeek）
```
RecommendationProvider（统一接口）
  generateRecommendations(context) → { results[], model, tokensUsed, latencyMs }
    ├ DeepSeekProvider        ← 默认
    ├ OpenAIProvider          ← 预留适配器
    └ QwenProvider / 其他     ← 预留
```
- 配置存云函数环境变量（provider / apiKey / 默认模型）。
- 支持按灰度路由不同用户到不同模型（为 V2 A/B 留口）。

### 8.2 结构化 Prompt → JSON 输出
- **System Prompt**：角色=资深礼物顾问；约束=规避禁忌、贴合预算与画像、不重复历史、输出 N 条结构化 JSON。
- **User Prompt**：对象画像 + 推荐参数 + 历史反馈摘要。
- **输出格式**：
```json
{
  "results": [
    {
      "name": "礼物名称",
      "reason": "结合画像的推荐理由",
      "priceRange": "100-200元",
      "purchaseHint": "京东/线下/定制",
      "tags": ["实用","颜值"],
      "matchScore": 92
    }
  ],
  "summary": "整体建议"
}
```

### 8.3 轻量学习闭环
- 推荐前查询该 `recipient_id` 最近 N 条历史推荐，提取 `accepted/rejected` 的礼物名 + 原因摘要。
- 注入 prompt：「该对象过去推荐过 A（已采纳）/ B（未采纳-原因），请参考避免重复、贴合偏好」。

### 8.4 降级与兜底
- AI 失败/超时 → 重试 1 次 → 仍失败返回**场景模板兜底清单** + 提示重试。
- 限流：单用户 QPS 限制防滥用。

### 8.5 成本控制
- 每次记录 `tokens_used` + 估算成本。
- Prompt 限长（历史摘要截断）。
- 日均消耗超阈值告警。

## 9. 变现与额度设计

### 9.1 广告位（微信流量主）
| 位置 | 类型 | 触发与频控 |
|---|---|---|
| 推荐首页底部、结果页中部、「我的」 | Banner | 常驻 |
| 推荐结果生成后 | 插屏 | 频控：每会话 ≤2 次，**首次推荐不插**（保转化） |
| 额度耗尽 | **激励视频**（核心） | 用户主动点「看视频 +3 次」，完成后回调校验发额度 |

### 9.2 额度规则（数值可后台配置）
| 来源 | 额度 | 说明 |
|---|---|---|
| 新人注册 | +3 次 | 首次登录发放 |
| 激励视频 | +3 次/条 | 看完一个视频 |
| 分享裂变 | +2 次/有效邀请 | 被邀请者首次进入才算 |
| 每日登录 | +1 次/天 | 每日首次进入领取，提升留存 |
| 消耗 | −1 次/推荐 | 生成一次推荐扣一次 |

- **对账**：以 `aigift_quota_logs` 流水为准，`users.free_quota` 为缓存字段；事务保证不超扣。

## 10. 数据模型（MySQL，`aigift_` 前缀）

> 共用 CloudBase 环境，通过表名前缀 `aigift_` 与其他小程序隔离。标签/画像/AI 结果用 JSON 列承载（MySQL 5.7+）。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `aigift_users` | `id`, `openid`(UQ), `nickname`, `avatar`, `free_quota`, `used_count`, `last_login_date`, `daily_login_claimed` | 用户与额度 |
| `aigift_recipients` | `id`, `owner_openid`(idx), `name`, `gender`, `age_range`, `relationship`, `occupation`, `personality`(JSON), `hobbies`(JSON), `material_prefs`(JSON), `taboos`(JSON), `completeness_score` | 对象画像 |
| `aigift_important_dates` | `id`, `recipient_id`(FK), `owner_openid`(idx), `date`, `occasion`, `is_recurring`, `notified` | 生日/纪念日提醒 |
| `aigift_recommendations` | `id`, `owner_openid`, `recipient_id`, `recipient_snapshot`(JSON), `input_context`(JSON), `model_provider`, `model_name`, `tokens_used`, `cost_estimate`, `latency_ms` | 推荐主记录 |
| `aigift_recommendation_items` | `id`, `recommendation_id`(FK), `recipient_id`(idx), `name`, `reason`, `price_range`, `purchase_hint`, `tags`(JSON), `match_score`, `feedback`(enum), `feedback_at` | 单条建议+反馈（便于 SQL 聚合采纳率） |
| `aigift_quota_logs` | `id`, `openid`, `type`(enum), `amount`, `balance_after`, `ref_id` | 额度流水对账 |
| `aigift_invites` | `id`, `inviter_openid`, `invitee_openid`(UQ), `rewarded` | 分享裂变 |
| `aigift_feedback` | `id`, `recommendation_id`, `openid`, `rating`, `comment` | 推荐整体满意度 |
| `aigift_analytics_events` | `id`, `openid`, `event_name`, `event_data`(JSON) | 漏斗/埋点 |

**设计要点**：
- 把"建议条目"从推荐记录拆出独立表 → 采纳率等质量指标可直接 `SELECT ... GROUP BY feedback` 聚合，无需解析 JSON。
- 推荐时对 `recipients` 做**快照**存入 `recommendations.recipient_snapshot`，对象日后修改不影响历史复现。
- 历史反馈查询基于 `recommendation_items` 的 `feedback` 字段。

## 11. 技术架构（对齐 fixbill，共用 CloudBase 环境）

### 11.1 隔离策略
| 资源 | fixbill | AIGift |
|---|---|---|
| CloudBase 环境 | `cloud1-1g2pvzhx7a072799` | **共用同一环境** |
| 云函数 | `fixbill_app` | `aigift_app`（独立） |
| 数据库表 | `fixbill_*` | `aigift_*`（独立） |
| 定时触发器 | `fixbill_*` | `aigift_*`（独立） |
| 环境变量 | `FIXBILL_MYSQL_*` | `AIGIFT_MYSQL_*` / `AIGIFT_AI_*` |

### 11.2 单一云函数 + 内部路由（复用 fixbill 目录结构）
```
cloudfunctions/aigift_app/
├── index.js              入口：Timer 分发 + 业务路由 + 鉴权注入
├── router.js             route→handler 映射 + PUBLIC_ROUTES + handlerCache
├── common/               db.js / constants.js(ErrorCodes) / response.js / security.js / utils.js(parseEvent)
├── middleware/           auth.js / errorHandler.js(BusinessError) / validator.js
└── modules/
    ├── user/             autoLogin, syncProfile, getUserInfo（含额度）
    ├── recipient/        create, update, delete, list, detail
    ├── recommend/        generate, regenerate
    ├── quota/            consume, rewardVideoCallback, shareReward, dailyLogin
    ├── reminder/         list, add, remove
    ├── share/            inviteCallback
    ├── feedback/         create
    └── system/           scanReminders（定时）, dbKeepAlive（定时）
```

### 11.3 路由与鉴权
- **统一响应**：`{ code, message, data }`；集中错误码（`common/constants.js`）。
- **公开路由**白名单（如 `user/autoLogin`）；其余经 `auth` 中间件，校验 openid 归属。
- **调用方式**：小程序 `wx.cloud.callFunction({ name: 'aigift_app', data: { route, data } })`；HTTP Gateway `POST /http/aigift_app`。

### 11.4 定时触发器（`aigift_` 前缀，复用 TIMER_ROUTE_MAP 模式）
| 触发器 | Cron（7段） | 路由 | 说明 |
|---|---|---|---|
| `aigift_daily_reminder` | `0 0 9 * * * *` | `system/scanReminders` | 每天 9:00 扫描当日到期提醒，下发订阅消息 |
| `aigift_db_keepalive` | `0 */20 * * * * *` | `system/dbKeepAlive` | MySQL 连接保活（复用 fixbill 经验） |

### 11.5 部署注意事项（复用 fixbill 经验）
- 部署用 `manageFunctions.updateFunctionCode`（非 `manageCloudRun`）。
- 触发器须**一次性传完整列表**（`createFunctionTrigger` 会整体替换，避免互相覆盖）。
- 部署后等待 10-30s 生效。

### 11.6 安全
- AI API Key 仅存云函数环境变量，绝不前端暴露。
- 所有写操作经云函数鉴权（openid 校验数据归属）。
- 云函数层做输入校验（防注入、长度限制、必填校验）。
- 数据库账号权限最小化。

## 14. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| AI 输出质量不稳定 | 推荐质量下降、用户流失 | 结构化 prompt + 兜底清单 + 持续调优 |

| 共用环境资源争抢 | 性能相互影响 | 前缀隔离 + 监控；必要时迁移独立环境 |
| 微信流量主审核/激励视频政策 | 变现受阻 | 提前过审、遵循平台规范、额度机制可配置 |
| 冷启动期推荐数据少 | 学习闭环效果弱 | 场景模板兜底 + 通用偏好先验 |
| 用户填写门槛 | 转化流失 | 模板预填 + 必填最小化 + 完整度引导 |
